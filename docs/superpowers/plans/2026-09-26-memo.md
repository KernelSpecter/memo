# memo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A zero-config Windows CLI that caches and replays the result of any command by tracing the file I/O of its whole process tree.

**Architecture:** A Cargo workspace. `memo.exe` launches the target process suspended, injects `memo_hook.dll` via vendored Microsoft Detours, and collects file-I/O events over a per-run named pipe. It fingerprints every input the tree read/probed/listed and every output it wrote; on a later run with identical inputs it replays recorded console output and restores output files without executing the command. Correctness rule throughout: when anything can't be fully observed, run the command untraced and don't cache — never replay a stale result.

**Tech Stack:** Rust (stable, MSVC, `+crt-static`), Microsoft Detours (vendored C++, built via `cc`), Windows APIs via `windows-sys`, BLAKE3, postcard+serde, rayon, named pipes, job objects.

**Spec:** `docs/superpowers/specs/2026-09-26-memo-design.md`

## Global Constraints

- Windows x86-64 only; no admin rights; Windows 10 1809+.
- Hook DLL and its dependencies must build with `-C target-feature=+crt-static` (no vcruntime dependency in injected processes).
- Never alter the return value/args of any hooked call; every hook body wrapped in `catch_unwind` + thread-local reentrancy guard; on internal error, call the original and (if possible) emit a taint.
- Never replay stale: any un-observable condition (uninjected child, WOW64 child, network, reparse-point create, open-by-id, missing check-in, external mid-run modification, non-zero exit without `--cache-failures`) makes the run uncacheable.
- All paths compared case-insensitively (case-folded key) but stored with original spelling.
- Content hashing and cache keys use BLAKE3. Cache format carries an integer `FORMAT_VERSION`; bump invalidates.
- Attribution on commits: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Author/committer: `KernelSpecter <KernelSpecter@users.noreply.github.com>`. Do not push to GitHub.

## Review Focus

- **Path normalization of odd forms** (`\??\`, UNC, `\Device\HarddiskVolumeN`, RootDirectory-relative, `NUL`/`CON`/pipes): a device misclassified as a file, or a volume path not mapped to a drive letter, poisons keys and fingerprints → tested in Task 4.
- **Read-then-write same path** (incremental compilers, `.pyc`, test caches): must fingerprint the *pre-run* state, not the post-run one, or the command never converges to a hit → tested in Tasks 6 and 15.
- **Listed-directory churn** (a tool writes a new file into a directory it also listed): the new file must be excluded from the listing fingerprint or the command never hits → tested in Tasks 6 and 15.
- **Child/grandchild that memo can't inject** (WOW64, or created via an uncovered path): must be caught via job accounting (`NoHello`) and taint, not silently dropped → tested in Task 14.
- **External modification during the run** (a file the tree read is changed by someone else before finalize): must taint, not store a fingerprint the command didn't actually observe → tested in Task 12.
